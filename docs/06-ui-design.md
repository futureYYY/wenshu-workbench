# 06 UI 设计与交互规范

> 文枢开发文档 · 第 6 篇。前端实现的唯一视觉依据。凡是本文没写到的地方，按第 1 节的原则自行判断，宁可克制，不要加装饰。

## 1. 设计理念：意图路由图

文枢做的事情，是把一条条文本送到它该去的地方：意图识别把文本**分流**到不同的意图，文本摘要把长文本**直达**到要点。这和地铁线网是同一个结构，所以整个界面借用地铁线路图的视觉语言：粗圆头的彩色线路、站点圆环、换乘枢纽、线路徽标、导视牌一样清楚的数字。

它不是装饰主题，而是信息系统：每一条彩色线都代表一个意图或一段进度，没有任何一条线是为了好看而画的。

**唯一的视觉焦点**：意图识别结果页的**线网图**，以及模型第一次输出某个新意图时“开通新线路”的那一刻。其次是运行中的**并行轨道**。除此之外，界面是安静的：墨色文字、白色版面、清楚的层级。

五条原则：

1. **线条承载信息**：彩色线只用来表示意图、进度和来源关系，不画装饰线、不用渐变。
2. **颜色属于数据**：界面本身只用墨色、白色和灰阶；彩色只出现在意图线路上；状态色只用在状态上，并且总是配图标和文字。
3. **像导视一样清楚**：大号导视数字、短标签、明确的方向。流程和时间从左到右，原文顺序从上到下。
4. **快而安静**：任何操作立刻有反馈；动效只在状态发生变化时出现。
5. **每页只有一个焦点**：一个页面里只有一处用力，其余都退后。

刻意避开的默认做法：紫蓝渐变背景、玻璃拟态和背景模糊、霓虹发光（暗色主题的线路微光除外）、一排排同样大小带柔和阴影的卡片、所有元素同一个圆角、装饰性插画和色块、表情符号。

**视觉参考**：画布“文枢界面样稿”画了 8 个关键界面（首页、设任务、任务运行中、识别结果的亮色和暗色、摘要对照阅读、提示词工坊、模型接入）。导出成图片后放在 `docs/images/`，实现时对照它们；样稿和本文细节不一致时，以本文为准。

## 2. 视觉语言要素

| 要素 | 形态 | 用在哪里 | 表示什么 |
|---|---|---|---|
| 线路 | 粗线，圆头圆角，转弯只用水平、竖直和 45° | 线网图、步骤条、进度、对照阅读 | 意图分流、流程、进度、来源关系 |
| 站点 | 圆环；未到为空心灰环，当前为墨色粗环，已过为实心 | 步骤条、进度、并行轨道、对照阅读的段落 | 一个步骤、一条数据、一个段落 |
| 枢纽 | 胶囊形的粗描边圆角矩形 | 线网图起点、Logo | 所有文本的出发点 |
| 线路徽标 | 实心胶囊，底色为线路色，内写意图名 | 结果表、筛选条、详情 | 一个意图 |
| 导视数字 | Overpass 粗体，等宽数字 | 计数、进度、耗时、压缩比 | 需要一眼读出的数 |

**Logo**：枢纽胶囊（24 × 14，墨色描边 2.5）左侧接入一段墨色短线，右侧分出两段短线，分别是线路色 1（蓝）和线路色 2（绿），表示“一进多出”。导航栏顶部只放符号（28 px）；favicon、托盘图标、exe 图标都用这个符号，16 px 时省略描边细节，只保留胶囊和两段彩线。文字标“文枢”用界面字体的粗体。

## 3. 设计令牌

全部写成 CSS 变量，放在 `frontend/src/design/tokens.css`，再在 Tailwind 的 `@theme` 里引用。组件里不允许出现硬编码的色值。

### 3.1 基础色

| 变量 | 亮色 | 暗色（夜间线网） | 用途 |
|---|---|---|---|
| `--bg` | `#F5F7FA` | `#0F1B2A` | 页面背景 |
| `--surface` | `#FFFFFF` | `#152436` | 面板、表格、抽屉 |
| `--surface-2` | `#EEF2F6` | `#1B2D42` | 悬停行、选中列、次级区域 |
| `--surface-3` | `#E3E9F0` | `#22374F` | 按下态、进度轨道底色 |
| `--border` | `#DCE2E9` | `#253A52` | 面板描边、表格分隔线 |
| `--border-strong` | `#C3CCD6` | `#34506E` | 输入框描边、未到站点 |
| `--ink` | `#1E2B38` | `#E8EEF5` | 主要文字、主按钮底色、焦点环、已过站点 |
| `--ink-2` | `#5E6B78` | `#A3B1C0` | 次要文字、时间、说明 |
| `--ink-3` | `#8A96A3` | `#74859A` | **只用于**禁用状态的文字，以及非文字的图形（跳过的进度段、浓缩计的原文线）。它在白底上对比度只有 3.0，不满足正文要求，任何需要阅读的文字（含占位符、列字母、未到站名、“空闲”、空状态说明）都用 `--ink-2` |
| `--on-ink` | `#FFFFFF` | `#0F1B2A` | 墨色底上的文字 |
| `--overlay` | `rgba(30, 43, 56, 0.24)` | `rgba(4, 10, 18, 0.60)` | 抽屉、对话框的遮罩 |

暗色不是亮色取反：背景是深靛蓝而不是黑色，像夜里亮着灯的线路图。

### 3.2 状态色

状态色只用于状态，并且**总是**和图标、文字一起出现，不单独用颜色表达状态。

| 变量 | 亮色 | 暗色 | 状态 |
|---|---|---|---|
| `--status-running` | `#1B64C8` | `#5AA2FF` | 运行中、处理中 |
| `--status-ok` | `#18794E` | `#3CCB7F` | 已完成、成功 |
| `--status-warn` | `#96590B` | `#F0B347` | 已暂停、限流等待、重试中、截断提示 |
| `--status-danger` | `#C2372F` | `#FF6B61` | 失败、错误 |
| `--status-muted` | `#5E6B78` | `#8D9BAB` | 已取消、跳过、等待中 |

### 3.3 线路色与分配

| 序号 | 亮色 | 暗色 | 名称 |
|---|---|---|---|
| 0 | `#0B6FD6` | `#4C9BFF` | 蓝 |
| 1 | `#2DBE6C` | `#3CCB7F` | 绿 |
| 2 | `#F2A900` | `#FFC53D` | 黄 |
| 3 | `#7B5CD6` | `#A08BFF` | 紫 |
| 4 | `#0EA5A4` | `#2ED3C6` | 青 |
| 5 | `#F2711C` | `#FF8F4C` | 橙 |
| 6 | `#C2368F` | `#F06CC0` | 玫红 |
| 7 | `#8C6D46` | `#C49A6C` | 棕 |
| 8 | `#4E7D22` | `#8CC152` | 橄榄 |
| 9 | `#2F4FA2` | `#6F8CFF` | 靛 |
| 10 | `#C23B3B` | `#FF6B6B` | 红 |
| 其他 | `#9AA5B1` | `#7A8796` | 灰 |

**分配规则**（后端已在 `category_colors_json` 中算好，前端直接用 `color_index`）：

- 每个任务内，意图按**第一次出现**的顺序依次取序号 0、1、2…10，之后不再改变，所以运行中颜色是稳定的；
- 第 12 个及以后出现的意图 `color_index = -1`，用“其他”灰；在线网图里合并成一条“其他 N 类”线路，在表格里仍显示各自的名称；
- 红色排在最后，只有意图很多时才会用到，避免和“失败”混淆。

**对比度规则**（在 `palette.ts` 里实现，不要手调）：

- 徽标文字：按 WCAG 相对亮度分别计算白字和墨色字（亮色主题 `#1E2B38`，暗色主题 `#0F1B2A`）的对比度，取较高的那个。上表的颜色已经调过，保证至少一种 ≥ 4.5：亮色主题下绿、黄、青、橙、灰用墨色字，其余用白字；暗色主题下全部用深色字；
- 线条描边：线路色与背景的对比度低于 3 时，给线条加 1 px 描边，描边色为线路色与黑色按 65 : 35 混合（`color-mix(in oklab, 线路色 65%, black)`）。地铁图常用的“线路描边”，同时解决浅色线看不清的问题；
- 暗色主题下线网图的线条加一层微光：`filter: drop-shadow(0 0 4px color-mix(in srgb, 线路色 45%, transparent))`。只有线网图这样做。

### 3.4 字体与字号

| 角色 | 字体 | 说明 |
|---|---|---|
| 界面与正文 | Noto Sans SC（可变字重） | 中文和其中的英文都用它，保证混排一致；字重只用 400、500、700 |
| 导视数字 | Overpass（可变字重） | 只用于数字和需要“导视感”的短英文：计数、进度、耗时、压缩比、行号、快捷键 |
| 等宽 | Overpass Mono，中文回落到界面字体 | 只用于提示词编辑器、原始输出、JSON |

三种字体都是 OFL 许可，用 Fontsource 的 npm 包随前端打包，不从网络加载（07 第 2.3 节）。界面字体之所以用最常见的 Noto Sans SC，是因为这套界面的个性来自线路语言和 Overpass 的导视数字，正文字体要的是稳定、清楚。想换成 HarmonyOS Sans SC 的话，按 07 第 2.3 节的办法替换。

```css
--font-sans: "Noto Sans SC Variable", "Microsoft YaHei UI", system-ui, sans-serif;
--font-num:  "Overpass Variable", var(--font-sans);
--font-mono: "Overpass Mono", var(--font-sans), ui-monospace, monospace;
```

导视数字一律 `font-variant-numeric: tabular-nums;`，用工具类 `.num` 应用。组件预览页上下并排显示 `111,111` 和 `888,888`，两者宽度必须一致；如果所用的 Overpass 文件不带等宽数字（`tnum`），表格和计数里的数字改用 Overpass Mono。

字号（像素 / 行高）：

| 令牌 | 字号 | 行高 | 字重 | 用途 |
|---|---|---|---|---|
| `xs` | 12 | 1.5 | 400/500 | 表头、徽标内的计数、快捷键 |
| `sm` | 13 | 1.55 | 400/500 | 次要信息、表格辅助列 |
| `base` | 14 | 1.7 | 400 | 界面正文、表格正文 |
| `md` | 16 | 1.8 | 400 | 阅读正文（对照阅读、条目详情的原文） |
| `lg` | 18 | 1.6 | 500 | 摘要主旨、抽屉标题 |
| `xl` | 22 | 1.4 | 700 | 页面标题 |
| `2xl` | 28 | 1.3 | 700 | 首页主标题 |
| `num-l` | 28 | 1.0 | 800 | 进度、计数（Overpass） |
| `num-xl` | 48 | 1.0 | 800 | 任务详情的进度百分比（Overpass） |

- 中文和数字、英文之间留一个空格，由文案保证（如“共 5,032 行”）；
- 阅读正文每行不超过 40 个汉字左右（约 680 px），表格和界面不受此限；
- 不用全大写，不用斜体表示强调，不单独给标题里的某个词换颜色。

### 3.5 间距、圆角、描边、阴影、层级

- 间距：4 px 为基数，只用 4、8、12、16、20、24、32、40、48、64。
- 圆角按层级区分，不要所有东西一个圆角：

| 对象 | 圆角 |
|---|---|
| 徽标、胶囊、开关、分段控件指示器 | 全圆（`9999px`） |
| 按钮、输入框、下拉框 | 8 px |
| 面板、首页始发站区域 | 14 px |
| 抽屉（只有靠内容一侧的两个角）、对话框 | 16 px |
| 表格单元格、行高亮 | 0 |
| 快捷键键帽 | 4 px |

- 描边：面板 1 px `--border`；输入框 1 px `--border-strong`；不要给面板加阴影，用描边区分层次。
- 阴影：只有浮层（抽屉、对话框、下拉、命令面板、toast）有阴影：
  - 亮色 `0 12px 32px -8px rgba(16,32,48,.24), 0 2px 6px rgba(16,32,48,.12)`
  - 暗色 `0 16px 40px -8px rgba(0,0,0,.55), 0 2px 8px rgba(0,0,0,.40)`
- 焦点环：`outline: 2px solid var(--ink); outline-offset: 2px;`，所有可交互元素统一，用 `:focus-visible`。
- 层级（z-index）：表头 10，导航栏 20，下拉与提示 40，抽屉 50，对话框 60，命令面板 70，拖放层 80，toast 90。

### 3.6 动效令牌

| 变量 | 值 | 用途 |
|---|---|---|
| `--dur-press` | 80 ms | 按下态 |
| `--dur-fast` | 140 ms | 悬停、开关、提示出现 |
| `--dur-base` | 220 ms | 抽屉、下拉、分段控件指示器、标签切换 |
| `--dur-slow` | 360 ms | 面板展开收起、布局切换 |
| `--dur-line` | 900 ms | 新线路开通 |
| `--ease-out` | `cubic-bezier(0.16, 1, 0.3, 1)` | 进入 |
| `--ease-in` | `cubic-bezier(0.7, 0, 0.84, 0)` | 离开 |
| `--ease-move` | `cubic-bezier(0.65, 0, 0.35, 1)` | 位移、尺寸变化 |

## 4. 布局与外壳

- 默认窗口 1600 × 1000，最小 1100 × 700。三档：1100–1279 紧凑，1280–1679 标准，≥ 1680 宽。
- 外壳：左侧导航栏 + 内容区。内容区顶部是页面栏，再往下是页面内容。

```
┌──────┬──────────────────────────────────────────────────────────────────┐
│  ⬭   │ 任务中心                                 [ 搜索或输入命令  Ctrl K ] │
│      ├──────────────────────────────────────────────────────────────────┤
│ 首页 │                                                                  │
│ 任务 │                         页面内容                                  │
│提示词│                                                                  │
│ 模型 │                                                                  │
│      │                                                                  │
│ 设置 │                                                                  │
│ 关于 │                                                                  │
│ ◐    │                                                                  │
└──────┴──────────────────────────────────────────────────────────────────┘
```

**导航栏**：宽 76 px，`--surface` 底、右侧 1 px 描边。顶部 Logo 符号；中间六个入口（首页、任务、提示词、模型、设置、关于），每个是 22 px 图标加 12 px 文字的竖排按钮，高 56 px；底部是主题切换按钮。当前入口：图标和文字用 `--ink`、字重 500，左边缘一条 4 px 宽、24 px 高的墨色竖线（像线路图上标注当前位置）；其余为 `--ink-2`。“任务”入口在有任务运行时，图标右上角显示一个 6 px 的 `--status-running` 圆点。

**页面栏**：高 56 px。左边页面标题（`xl`），首页不显示标题；右边是命令面板入口，样子像一个搜索框，文字“搜索或输入命令”，右侧显示键帽 `Ctrl` `K`。与后端的实时连接断开时，在入口左边显示一个 `--status-warn` 的小标签“正在重新连接”，连接正常时什么都不显示。

**内容区**：左右内边距 32 px（紧凑档 24 px）。表单类内容最大宽 880 px；阅读类最大宽 720 px 一栏；数据类铺满。

**全局浮层**：命令面板、toast、拖放层、抽屉都挂在外壳上，任何页面都能用。

**主题**：`<html data-theme="light|dark">`。`index.html` 里放一段内联脚本，在样式加载前读取 `localStorage` 的 `wenshu.theme` 和系统设置并写好 `data-theme`，避免闪一下白屏。切换主题时，用 `document.startViewTransition` 做 220 ms 的淡入淡出（不支持时直接切换）。

## 5. 组件规范

组件分三层：`components/metro/` 是视觉语言组件，`components/base/` 是基础组件（在 Reka UI 无样式组件上自绘），`components/data/` 和 `components/editor/` 是数据和编辑器组件。

### 5.1 视觉语言组件

#### LineBadge 线路徽标

- 表示一个意图。实心胶囊，高 22 px（`sm`）或 26 px（`md`），左右内边距 10 px，底色为线路色，文字颜色按第 3.3 节自动选择，13 px、字重 500；
- 可带计数：名称后加一条 1 px 竖线分隔，计数用导视数字；
- 最长 160 px，超出省略，悬停 400 ms 后用提示显示全名；
- 人工修正过的（P1）：胶囊左端内侧加一个 6 px 白点，提示写“人工修正，模型原输出为‘退款咨询’”；
- 可编辑变体（P1）：点击打开下拉，列出本任务已有的意图（带颜色）和一项“新的意图…”。

#### StationDot 站点

- 尺寸：8、12、16、64 px（首页始发站）。描边宽度分别为 2、2.5、3、6 px。
- 状态：

| 状态 | 外观 |
|---|---|
| 未到 | `--border-strong` 描边，`--surface` 填充 |
| 当前 | `--ink` 描边加粗一档，`--surface` 填充，外圈一个 2 秒一周期的呼吸光环（这是全应用唯一允许循环播放的动画，减少动态效果时关闭） |
| 已过 | `--ink` 或线路色实心 |
| 出错 | `--status-danger` 描边，16 px 及以上尺寸中间加“!” |
| 暂停 | `--status-warn` 描边，16 px 及以上尺寸中间加暂停符号 |

#### MetroStepper 站点步骤条

用于新建任务。四个站：选文件、选数据、设任务、开始。

```
  ●━━━━━━━━━━━━━━●━━━━━━━━━━━━━━◉┄┄┄┄┄┄┄┄┄┄┄┄┄┄○
选文件           选数据          设任务          开始
```

- 线宽 4 px。已过的线段为 `--ink` 实线，未到的线段为 `--border-strong` 虚线（6 px 实、4 px 空）；
- 站名在站点下方：当前站 14 px 字重 700 `--ink`；已过站 13 px `--ink-2`，可点击回到该站；未到站 13 px `--ink-2`、字重 400，不可点击（与已过站靠站点样式和能否点击区分，不靠更浅的文字）；
- “选文件”站在上传时，站点圆环按上传进度画出一圈墨色弧线；
- 站与站之间移动时，线段由左向右填充墨色（220 ms）。

#### LineProgress 线路进度

| 变体 | 用在哪里 | 尺寸 |
|---|---|---|
| 迷你 | 首页、任务中心的列表行 | 宽 160–240 px，线宽 3 px，右侧只显示“62/100” |
| 完整 | 任务详情顶部 | 铺满，线宽 6 px，带起点、终点站和下方的数据行 |

- 线段从左到右依次是：跳过（`--ink-3`）、成功（`--ink`）、失败（`--status-danger`），之后是未完成的轨道（`--surface-3`）；
- 已完成部分的末端是一个“当前”站点；任务暂停时换成暂停站点；任务完成时终点站变实心；
- 完整变体下方数据行（导视数字）：`已完成 62 / 100`、`失败 2`、`42 条/分`、`约 50 秒后完成`；完成后显示 `用时 2 分 13 秒`；
- 数字变化用 300 ms 的滚动过渡，宽度变化用 `--ease-move`。

#### LineMap 线网图

意图识别结果的主角。输入：`categories`（`CategoryStat[]`）、失败数、是否运行中。


几何规则：

- SVG 绘制，尺寸随容器变化（`ResizeObserver`）；
- 左侧是枢纽胶囊，上方标注“全部 N 条”；右侧留 260 px 放终点站标签；
- 线路按条数从多到少、从上到下排列。线宽 `3 + 9 × sqrt(count / 最大 count)`，范围 3–12 px；
- 所有线路从枢纽出发时上下并排成一束（各线之间留 2 px），并排水平走一段（约为枢纽到终点距离的三分之一，至少 64 px）后各自以 45° 转向自己终点站的高度，再水平走到终点。外侧的线先转、内侧的线依次晚 14 px 转，保证斜线段之间也留有间隙；并排顺序与终点顺序一致，线路之间不会交叉；转角用 10 px 圆角（斜线太短时缩小）；
- 终点站是站点圆环，半径 `max(6, 线宽/2 + 3)`，描边为线路色；
- 终点标签一行：意图名（14 px，字重 500，最长 140 px）、条数（导视数字 20 px，右对齐成一列）、占比（13 px `--ink-2`）；
- 最多画 11 条彩色线路；`color_index = -1` 的意图合并成一条灰色“其他 N 类”，点击弹出这些意图的清单，每项可点击筛选；
- 有失败时，最下方加一条从枢纽出发的 `--status-danger` 虚线（6 px 实、6 px 空），终点为空心圆，标签“未到站（失败） N”，后面跟一个“查看”文字按钮；
- 行距 `clamp((高度 − 上下边距) / 线路数, 34, 64)` px；
- 运行中、还没有结果时：只画枢纽和一条 `--border-strong` 的虚线，标签“第一条结果到站后，线路会出现在这里”。

交互：

- 悬停某条线或它的标签：这条线保持不透明，其余线降到 0.2 不透明度；终点旁出现提示：“物流查询 412 条（32.1%）”，下面列出 3 条示例原文（首次悬停时请求 `items?label=…&limit=3`，结果缓存）；
- 点击：按这个意图筛选下方结果表，再点一次取消；按住 Shift 点击可多选；被选中的标签外加 2 px 墨色描边；Esc 清除筛选；
- 键盘：每个终点标签可以 Tab 聚焦，↑↓ 在线路间移动，Enter 等同点击；
- 运行中：条数和线宽随数据变化平滑过渡（300 ms）；新意图出现时播放“开通新线路”动画（第 8.1 节）；线路按条数重新排序时终点平移过去（360 ms），运行中最多每 2 秒重排一次，避免抖动；
- 无障碍：SVG 加 `role="img"` 和概括性的 `aria-label`（“共 1,284 条，5 个意图，最多的是物流查询 412 条”）；终点标签是真实的可聚焦文字元素，屏幕阅读器可以逐条读到。


- 选了多列时，出现拼接方式分段控件“带列名 / 只拼值”，预览框随之更新；
- 文本类文件（txt、md、粘贴）没有工作表和表头选项，表格只有“行号”和“文本”两列，文本列默认选中；
- 文件被截断（超过 10 万条）时，顶部显示 `--status-warn` 提示条“只读取了前 100,000 条”。

**设任务**：

```

             从第 [ 2 ] 行开始
 相同文本只调用一次   [开]   本次能省 312 次调用
```

- 任务类型是两块并排的选择块，选中块描边 2 px `--ink`；切换类型时，提示词、模型、并发跟着换成该类型的默认值（用户手动改过的不覆盖）；
- “查看”在 Popover 里预览提示词全文；“编辑”在新的路由打开提示词工坊，返回后保留本页状态；
- 模型下拉里每项显示名称、模型名、最近延迟，停用的模型不可选；
- “全部”后面显示实际条数；
- “本次能省 N 次调用”来自预估接口，开关切换后重新请求预估。

**开始**（确认）：

```

 并发 5，失败自动重试 2 次，相同文本只调用一次（省 12 次）

```

- 这一页的文字就是一句话加几行要点，不用表格；
- `warnings` 逐条显示，前面加 `--status-warn` 图标；
- 点击“开始处理”后按钮进入加载状态，创建成功后跳到任务详情，步骤条的线路通过 View Transitions 变成任务详情顶部的线路进度。

### 6.4 任务详情：意图识别（`/jobs/:id`）

**页头**：任务名（点击可改名，Enter 保存，Esc 取消）、类型、文件名、模型、提示词版本；右侧操作按状态变化：

| 状态 | 操作 |
|---|---|
| 运行中 | 暂停、取消 |
| 已暂停 | 继续、取消；有失败时“重试失败项” |
| 已完成 | 导出（下拉）；有失败时“重试失败项 (N)”；P1“再跑一次” |
| 已取消 | 导出、删除 |

`status_reason_code` 不是 `user_pause` 时，页头下方出现提示条，文字是“已暂停：”加 `status_reason`，例如“已暂停：模型密钥无效或无权限（HTTP 401）”，后面的操作与任务中心相同（第 6.3 节）；“去修改模型”打开 `/models?edit={模型 id}`。

**完整线路进度**横跨页头下方，左边是大号百分比（`num-xl`），右边是第 5.1 节的数据行。

### 6.5 任务详情：文本摘要

- 运行中：左边并行轨道（并发高的摘要任务同样适用），右边是浓缩计和“已完成摘要的平均压缩比”；
- 完成后：页头下方是浓缩计（合计），下面是结果表；
- 点击某行进入对照阅读 `/jobs/:id/read/:itemId`（第 5.1 节 ExpressTrace）；
- 失败和截断的条目在表里用状态标签标出，悬停显示原因；
- **人工复核**（01 RES-11）：结果表按 E 进入对照阅读并直接开始修改，按空格切换“已复核”；人工修改过的摘要在表里有铅笔标记。
  对照阅读的顶部有“标记已复核”和“修改摘要”：右栏的摘要主旨变成编辑框，要点保持模型输出，Ctrl+Enter 或“保存”写入，
  Esc 或“取消”放弃；有未保存的修改时不能切换条目，关闭窗口会提醒。改过的摘要标题旁标“人工修改”，
  下方是可展开的“模型原摘要”和“撤销修改”。字数、压缩比和导出都按修改后的摘要。

  提示词没有列出类别时不显示菜单，结果下方说明“这个任务的提示词没有按“- 类别名：说明”列出意图类别，不能人工修正。”；
- 页头的“标记已复核 / 已复核”切换复核状态，任何状态的条目都可以标记。

### 6.9 设置（`/settings`）

分组的单栏表单，修改后立即保存，toast“已保存”。

| 分组 | 内容 |
|---|---|
| 任务默认值 | 意图识别并发、文本摘要并发（Slider）；处理条数（分段控件：数字或全部）；失败重试次数；相同文本只调用一次 |
| 外观 | 主题：跟随系统、亮色、暗色，三个选项各带一张缩小的界面示意 |
| 启动 | 打开方式：独立窗口、默认浏览器；端口（说明“重启后生效”） |
| 数据 | 运行方式（打包版、源码版或开发模式）；数据目录路径和“打开”；日志目录“打开”；版本号；一行说明“API Key 加密保存在本机，加密用的密钥是数据目录里的 secret.key，删除它会让已保存的 API Key 失效” |
| 演示模型 | 在模型列表中显示演示模型 |

### 6.10 命令面板（Ctrl+K）

- 居中偏上的浮层，宽 640 px；输入框占位文字“搜索任务、提示词，或输入命令”；
- 分组：操作（新建任务、粘贴文本开始、接入模型、切换主题、打开数据目录、查看快捷键）、任务（按名称模糊搜索，显示状态）、提示词、模型；
- ↑↓ 选择，Enter 执行，Esc 关闭；每项右侧显示对应快捷键；
- 空输入时显示最近使用的 5 项。

### 6.11 拖放层

- 文件拖进窗口任意位置：整个窗口出现 `--overlay` 遮罩和居中的大号始发站圆环，文字“松开，开始新任务”；
- 拖入的明显是图片、音频、视频（MIME 以 `image/`、`audio/`、`video/` 开头）时，圆环变为出错样式，文字“不支持这种文件，支持 txt、md、csv、xlsx、xls”。其他情况一律放行，交给上传接口按扩展名判断（不支持时返回 415，再用 toast 说明）：Windows 上装了 Excel 时 `.csv` 的 MIME 是 `application/vnd.ms-excel`，`.md` 常常为空，按白名单判断会误拒；
- 松开后：上传，进入 `/new?file={id}` 的“选数据”站；
- 在首页或新建任务的第一站，焦点不在输入框时按 Ctrl+V：直接把剪贴板文本作为“粘贴文本”开始。

### 6.12 首次使用

不做弹窗教程。首次打开时默认模型是演示模型，首页底部模型条提示“现在用的是演示模型，结果是模拟的”和“接入真实模型”。模型页空的时候（只有演示模型），列表下方显示 EmptyState：“接入一个 OpenAI 兼容接口，就能处理真实数据”和主按钮“接入模型”。

### 6.13 关于（`/about`）

公开版的自述页：产品定位、名字的由来（文 = 文本，枢 = 枢纽，Logo 一进多出）、能解决的问题、适合谁、五步用法、作者与联系方式、赞赏二维码。赞赏完全自愿，不影响功能；二维码只在“赞赏支持”抽屉里出现，不占用主页面空间。

## 7. 交互规范

### 7.1 反馈时效

| 情况 | 要求 |
|---|---|
| 点击、按键 | 100 ms 内有可见变化（按下态、选中态、焦点移动） |
| 本地可完成的操作 | 300 ms 内出结果 |
| 需要等待 400 ms 以上的内容 | 用骨架占位，保持最终布局，不用整页转圈，不用全屏遮罩 |
| 长时间操作（上传、测试连接、导出） | 显示具体进度或阶段文字，如“正在读取第 3 万行” |

### 7.2 乐观更新与撤销

- 暂停、继续、取消、改名、修正意图、标记复核：界面立刻改变（任务详情页的状态在接口返回前不被实时事件改回去），接口失败时回滚并 toast 说明原因；修改摘要是编辑框里点“保存”才写入；
- 删除没有结果的任务、提示词、模型：立刻从列表消失，toast 带“撤销”，6 秒后才调用删除接口；关闭窗口前若有待执行的删除，立即执行；
- 只有不可撤销且后果严重的操作才用确认对话框：删除带有结果的任务（说明“N 条结果会一起删除，无法恢复”），确认后立即删除，不再提供撤销；没有结果的任务按上一条走撤销。

### 7.3 键盘

| 快捷键 | 作用 | 范围 |
|---|---|---|
| Ctrl+K | 命令面板 | 全局 |
| Ctrl+N | 新建任务 | 全局 |
| Ctrl+, | 设置 | 全局 |
| Ctrl+Shift+L | 切换亮色、暗色 | 全局 |
| ? | 快捷键一览 | 全局，焦点不在输入框时 |
| Esc | 关闭最上层浮层；没有浮层时清除筛选 | 全局 |
| Enter | 下一站；最后一站为开始处理 | 新建任务 |
| Alt+← | 上一站 | 新建任务 |
| Ctrl+V | 用剪贴板文本开始 | 首页、新建任务第一站 |
| ↑ ↓ 或 K J | 上一条、下一条 | 结果表、条目抽屉、对照阅读 |
| Enter | 打开条目详情 | 结果表 |
| / | 聚焦搜索框 | 结果表、任务中心 |
| P | 暂停或继续当前任务 | 任务详情 |
| R | 重新处理当前条目 | 条目抽屉 |
| E | 修正意图、修改摘要 | 结果表、条目抽屉、对照阅读 |
| 空格 | 标记已复核（再按一次取消） | 结果表 |
| Ctrl+S | 保存 | 提示词工坊 |
| Ctrl+Enter | 试运行 | 提示词工坊 |

快捷键在提示和命令面板里都显示；单字母快捷键在输入框内不生效。

### 7.4 焦点管理

- 抽屉、对话框、命令面板打开时焦点进入，Tab 只在其中循环；关闭后焦点回到触发它的元素；
- 页面跳转后焦点移到页面标题（首页移到始发站区域）；
- 焦点环在所有主题下都清晰可见，不允许 `outline: none` 而不提供替代。

### 7.5 不丢工作

- 提示词草稿自动保存（第 6.7 节）；
- 新建任务流程中，在同一会话里离开再回来，保留已选的文件和选项（存在 Pinia，不持久化）；
- 有未保存修改时，关闭标签页或窗口触发浏览器的 `beforeunload` 提醒；
- 后端在任务运行中退出，下次打开任务处于“已暂停”，原因写清楚，点“继续”即可。

### 7.6 加载、空、错误状态

- 每个数据区域都要设计这三种状态，验收时逐一检查；
- 错误文案的结构：发生了什么 + 原因（知道时）+ 下一步，下一步做成按钮。例如“连不上 api.deepseek.com：请求超时（120 秒）。”加按钮“重试失败项”“去检查模型”；
- 空状态是一次邀请：一句话说明能做什么，加一个主按钮。

### 7.7 实时数据的呈现

- SSE 事件到达后先合并，再用 `requestAnimationFrame` 统一更新界面，每秒最多更新 10 次；
- 数字用滚动过渡（300 ms），不要每次跳变；
- 结果表只对可见区域做“新到行”闪烁；用户正在滚动或选中某行时，新数据不能让列表跳动（追加在尾部，不改变当前位置）；
- 断线时页面栏显示“正在重新连接”；重连成功后重新拉取当前数据，标签消失。

### 7.8 窗口标题与通知

- 窗口标题：没有运行中的任务时为“文枢”；有一个时为“(62%) 文枢”；多个时为“(2 个运行中) 文枢”；
- P1：任务完成时，若窗口不在前台，用浏览器通知（需要用户授权，首次在设置里请求）提示“客服对话0915 意图识别已完成，成功 98 条，失败 2 条”。

## 8. 动效规范

### 8.1 签名时刻

全应用只有这三处“表演性”动效，其余都是功能性过渡：

1. **开通新线路**：意图识别运行中，模型第一次输出一个新意图时，线网图从枢纽画出这条新线路（`stroke-dashoffset` 动画，`--dur-line`），线画到终点时终点站弹出（缩放 0.6→1，220 ms），名称和计数淡入，计数从 0 滚到实际值。同一时间多个新意图依次错开 150 ms；
2. **到站**：每完成一条，对应线路终点的计数滚动更新（300 ms），线宽平滑变化（300 ms，`--ease-move`）；并行轨道上的车厢滑出、新车厢滑入（各 160 ms）；
3. **全部到站**：最后一条完成时，并行轨道面板收起（360 ms），线网图用 FLIP 方式展开到整宽（360 ms），终点站同时完成一次从左到右的依次点亮（每站间隔 40 ms）。

### 8.2 功能性过渡

| 场景 | 动效 |
|---|---|
| 抽屉 | 从右侧滑入 24 px 并淡入，`--dur-base`、`--ease-out`；离开 180 ms、`--ease-in` |
| 下拉、提示、Popover | 缩放 0.98→1 并淡入，`--dur-fast`；关闭时立即消失，不做退场动画：Reka UI 的这几种浮层在退场动画期间仍算最上层，这时按 Esc 会被正在消失的浮层接走，抽屉、对话框就关不掉 |
| 标签页、分段控件 | 指示器滑动，`--dur-base` |
| 折叠面板 | 高度过渡，`--dur-slow`、`--ease-move` |
| 路由切换 | 内容区 120 ms 淡入；新建任务到任务详情、首页到新建任务使用 View Transitions 让线路“延续”过去 |
| 按钮按下 | `scale(0.98)`，`--dur-press` |

明确不做：页面加载时各区块依次上浮淡入、卡片悬停上浮、滚动触发的入场动画、背景流动渐变。

### 8.3 减少动态效果

检测 `prefers-reduced-motion: reduce`：

- 关闭线路描画、站点呼吸光环、车厢滑动、新行闪烁、骨架呼吸；
- 数字直接更新，不滚动；
- 保留不超过 120 ms 的淡入淡出，保证状态变化仍然可感知。

## 9. 文案规范

- **语气**：简洁、直接、平实，用动词开头；不用感叹号、语气词、表情；错误不道歉，不说“哎呀”；
- **说用户的话**：说“接入模型”，不说“新增 Provider 配置”；说“处理条数”，不说“limit”；
- **同一个动作全程同名**：

| 按钮 | 完成后的 toast 或状态 |
|---|---|
| 开始处理 | 已开始处理 |
| 暂停 | 已暂停 |
| 继续 | 已继续 |
| 取消任务 | 已取消 |
| 重试失败项 | 已重新排队 N 条 |
| 重新处理 | 已重新排队 |
| 导出 | 已导出 {文件名} |
| 保存 | 已保存为 v8 |
| 测试连接 | 连接正常 / 具体失败原因 |
| 恢复此版本 | 已恢复为 v5（新版本 v9） |
| 修改意图 | 行内显示“人工修正”和“修正前”（不弹 toast） |
| 撤销修正 | “人工修正”标记消失 |
| 修改摘要 → 保存 | 已保存修改 |
| 撤销修改 | 已撤销修改 |
| 标记已复核 | 按钮变为“已复核” |

- **数字和单位**：千分位“1,284”；时间“2 分 13 秒”“约 50 秒”“820 毫秒”（表格和导视数字里可用“820ms”“2.1s”）；百分比保留一位小数“32.1%”；倍数用乘号“15×”；中文和数字之间留空格；
- **日期**：今天显示“10:02”，昨天“昨天”，一周内“周一”，今年“9月20日”，更早“2025年9月20日”；
- **禁止**：“操作成功”这类不说明内容的提示；“请稍候…”（改为具体阶段）；“点击这里”；全大写英文；按钮文字末尾加箭头；用“·”串起来的一串元信息。

## 10. 可访问性

- 文字对比度满足 WCAG AA（正文 ≥ 4.5，大字 ≥ 3）；线条和图形与背景 ≥ 3（第 3.3 节的描边规则保证）；
- 颜色从不单独表达信息：意图总有名称，状态总有图标和文字；
- 全部功能可以只用键盘完成（第 7.3 节）；
- 进度变化用 `aria-live="polite"` 区域播报，最多每 10 秒一次（“已完成 62 条，共 100 条”）；
- 线网图有文字替代（第 5.1 节）；图标按钮都有 `aria-label`；
- 尊重减少动态效果（第 8.3 节）。

## 11. 禁止清单

- 紫色、蓝紫渐变背景；任何装饰性渐变；
- 玻璃拟态、背景模糊卡片；
- 一排排大小相同、带同样柔和阴影的卡片；所有元素统一一个圆角；
- 装饰性插画、色块、表情符号；
- 标题上方的小号全大写标签；只为了装饰的编号（01、02、03），除非内容本身是有顺序的步骤；
- 用等宽字体排小号标签；
- 按钮文字后面加箭头；
- 页面加载时各区块依次上浮的入场动画、悬停上浮；
- 只有转圈、没有说明的加载状态；
- 非破坏性操作用确认弹窗；
- 只写“成功”“失败”而不说明是什么的提示。

## 12. UI 验收清单

- [ ] 亮色、暗色两套主题下，每个页面都检查过一遍，没有硬编码颜色
- [ ] 首页拖入文件到看到“选数据”预览，全程不超过 3 秒（1 MB 的 xlsx）
- [ ] 新建任务四站都能只用键盘走完
- [ ] 运行中的任务：并行轨道行数等于并发数，限流等待和重试有可见状态
- [ ] 线网图：新意图出现时有开通动画；超过 11 个意图时出现“其他 N 类”；有失败时出现“未到站”线；点击线路能筛选结果表
- [ ] 10 万行结果表滚动不卡顿，搜索和筛选不阻塞界面
- [ ] 条目抽屉的每个标签页都有内容或被隐藏，没有空白页

- [ ] 提示词工坊：变量高亮和补全可用；草稿恢复可用；离开未保存页面有提醒

- [ ] 每个数据区域都检查过加载、空、错误三种状态
- [ ] 所有可交互元素都有可见焦点环，Tab 顺序合理
- [ ] 开启系统“减少动态效果”后，第 8.3 节列出的动效全部关闭

- [ ] 窗口标题随运行进度变化
