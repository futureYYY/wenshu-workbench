# 01 需求说明

> 文枢（WenShu）开发文档 · 第 1 篇，共 8 篇。本文定义“做什么”，“怎么做”见 02 至 07。
> 版本 1.0，2026-10-21。

## 1. 背景与目标

需要一个在自己电脑上使用的小工具：把一批文本（来自 txt、csv、Excel）逐行交给大模型处理，完成两类任务：

- **意图识别**：判断每条文本属于哪个意图类别；
- **文本摘要**：为每条（通常较长的）文本生成摘要。

模型通过 OpenAI 兼容接口接入：云端 API、公司内网模型网关、本机 Ollama 或 vLLM 都可以。两类任务各有一套可修改的提示词，模型可以在界面里自定义接入和修改。

目标：

1. 一次上传、一键开始，处理过程看得见，结果能查、能校对、能导出；
2. 提示词和模型在界面里随时调整，改完立刻试运行；
3. 一键启动：双击 `WenShu.exe`（打包版）或项目根目录的 `启动文枢.bat`（源码版），像原生软件一样打开；
4. 界面与交互达到顶级桌面软件水准（规范见 06）；
5. 前后端分离，源码完整可读，配有 README，方便以后自己改。

## 2. 用户与场景

只有一个用户：开发者本人，在自己的 Windows 笔记本上使用，不需要登录和权限。

| 场景 | 过程 |
|---|---|
| 意图识别试跑后全量 | 拿到 5,000 行客服对话 Excel，先处理 100 行，看类别分布和判断依据；觉得类别定义不准，就去改提示词，再处理全部 |
| 批量摘要 | txt 或 Excel 里每行是一篇几百到上万字的文本，批量生成摘要并导出 Excel |
| 调提示词 | 在提示词工坊里修改，挑一条真实数据试运行，满意后保存；之后新建的任务自动用新版本 |
| 换模型对比 | 同一份数据分别用两个模型各跑一次，对比结果 |

## 3. 名词

| 名词 | 含义 |
|---|---|
| 任务类型 | 意图识别（`classify`）或文本摘要（`summarize`） |
| 任务 | 一次处理：某个文件的若干行 × 一个任务类型 × 一个提示词版本 × 一个模型 |
| 条目 | 任务里的一条待处理数据，对应文件中的一行 |
| 提示词模板 | 一套提示词（系统提示词、用户消息模板、输出解析规则），属于某个任务类型 |
| 模型配置 | 一个 OpenAI 兼容接口的接入信息：地址、密钥、模型名、参数 |
| 并发 | 同一任务同时在请求模型的条目数，1 到 20 |
| 处理条数 | 本次任务最多处理多少条，默认 100，可选“全部” |
| 演示模型 | 程序内置的模拟模型接口，不需要密钥、不联网，用于试用和自动化测试 |
| 线网图、并行轨道、对照阅读 | 界面组件，定义见 06 |

## 4. 功能需求

优先级：**P0** 第一版必须有；**P1** 第一版之后紧接着做；**P2** 以后再说。
编号在开发计划（08）和提交说明里引用。

### 4.1 数据导入（IMP）

| 编号 | 优先级 | 需求 |
|---|---|---|
| IMP-01 | P0 | 拖拽或点击上传文件：`.txt` `.md` `.csv` `.xlsx` `.xls`；单个文件不超过 50 MB |
| IMP-02 | P0 | 粘贴文本：粘贴多行文本，按行生成数据，等同于上传一个 txt |
| IMP-03 | P0 | csv、txt 自动识别编码：UTF-8、UTF-8 BOM、GB18030（兼容 GBK）、UTF-16；csv 自动识别分隔符：逗号、制表符、分号、竖线 |
| IMP-04 | P0 | Excel 多个工作表：列出全部工作表及行数，由用户选择其一 |
| IMP-05 | P0 | 表头：默认第 1 行是表头，可改为第 N 行，或选“无表头”（列名用 A、B、C…） |
| IMP-06 | P0 | 上传后 3 秒内显示前 200 行预览，同时给出总行数、空行数 |
| IMP-07 | P0 | 选择文本列：可选 1 列或多列；多列时按“列名：值”逐行拼接，并预览第一条拼接结果。自动推荐平均字数最多的文本列 |
| IMP-08 | P0 | 一行就是一条待处理数据。txt、md 的每个非空行是一条；表格的每个数据行是一条；文本为空的行跳过并计数 |
| IMP-09 | P0 | 同一文件重复上传时按内容哈希识别，直接复用已有记录 |
| IMP-10 | P0 | 单个工作表或文本最多读取 10 万条数据，超出部分不读取，并明确提示 |
| IMP-11 | P1 | `.docx`（按段落，或整篇一条）、`.pdf`（只支持有文字层的，按页或整篇一条） |
| IMP-12 | P1 | txt 的切分方式可选：按行、按空行分段、整篇一条 |

### 4.2 新建任务（JOB）

| 编号 | 优先级 | 需求 |
|---|---|---|
| JOB-01 | P0 | 任务类型二选一：意图识别、文本摘要 |
| JOB-02 | P0 | 选择提示词模板，默认选中该任务类型的默认模板；可一键跳去编辑 |
| JOB-03 | P0 | 选择模型，默认选中该任务类型的默认模型；显示最近一次测试的结果和延迟 |
| JOB-04 | P0 | 并发：1 到 20，默认 5。两种任务类型各有自己的默认值，在设置里修改 |
| JOB-05 | P0 | 处理条数：默认 100；可填自定义数字，或选“全部”（不设上限，处理完所选数据） |
| JOB-06 | P0 | 起始行：默认从第一条数据开始，可指定原文件行号，用于分批处理 |
| JOB-07 | P0 | “相同文本只调用一次”，默认开启：同一任务内发给模型的内容完全相同的条目只请求一次，结果共享；界面显示能省下多少次调用。判断依据是渲染后的完整提示词，不只是原文（03 第 4.7 节） |
| JOB-08 | P0 | 开始前显示预估：条数、跳过的空行数、重复条数、预计 tokens、预计耗时区间、超长文本数量和处理方式 |
| JOB-09 | P0 | 任务名默认“文件名 + 任务类型”，可修改 |
| JOB-10 | P1 | 按文件结构记住上次的选择（文本列、模型、提示词、并发），下次自动套用 |
| JOB-11 | P1 | “再跑一次”：复制一个已有任务的全部配置新建任务，可改模型或提示词 |

### 4.3 任务执行（RUN）

| 编号 | 优先级 | 需求 |
|---|---|---|
| RUN-01 | P0 | 后台执行，关闭界面窗口不影响；可以同时运行多个任务 |
| RUN-02 | P0 | 严格遵守任务的并发数；同一模型被多个任务共用时，总并发不超过该模型配置的“并发上限” |
| RUN-03 | P0 | 实时进度：已完成、失败、剩余、速度（条/分钟）、预计剩余时间；并行轨道显示每个并发槽正在处理哪一行、已用时、所处阶段 |
| RUN-04 | P0 | 暂停、继续、取消。暂停时不再派发新条目，进行中的条目处理完后停下 |
| RUN-05 | P0 | 失败自动重试，默认 2 次，指数退避；遇到 429 时遵守 `Retry-After`。重试和等待状态在界面上可见 |
| RUN-06 | P0 | 密钥无效（401、403）或模型不存在（404）时整个任务自动暂停，说明原因并提供“去修改模型”；修好后点“继续” |
| RUN-07 | P0 | 熔断：连续 10 条因超时、连不上或服务端错误失败时，任务自动暂停并写明最后一次错误 |
| RUN-08 | P0 | “重试失败项”：把失败条目重新排队处理 |
| RUN-09 | P0 | 程序退出时，运行中的任务自动暂停，原因写“程序退出”；下次打开可以继续，已完成的结果不丢 |
| RUN-10 | P0 | 长文本：意图识别超出模型上下文时保留首尾、截去中间并标记；摘要超出时自动分段摘要再合并 |
| RUN-11 | P0 | 兼容思考模型：剔除 `<think>` 内容和 `reasoning_content` 后再解析，思考内容单独保存、可查看 |
| RUN-12 | P1 | 运行中调整并发，立即生效 |
| RUN-13 | P1 | 自适应限流：连续出现 429 时自动降低实际并发，恢复后逐步回升 |
| RUN-14 | P1 | 任务完成时，若窗口不在前台，发系统通知 |

### 4.4 结果查看与校对（RES）

| 编号 | 优先级 | 需求 |
|---|---|---|
| RES-01 | P0 | 结果表：行号、原文、结果列、状态；按状态、意图筛选，按关键词搜索；10 万行也能流畅滚动 |
| RES-02 | P0 | 意图识别：线网图显示各意图的条数和占比，点击某条线路即筛选结果表。类别从模型输出中动态汇总，不需要预先定义，数量不限 |
| RES-03 | P0 | 条目详情：原文、实际发给模型的消息、原始输出、解析结果、思考内容、耗时、tokens、每次尝试的记录 |
| RES-04 | P0 | 单条重新处理 |
| RES-05 | P0 | 文本摘要：结果表显示摘要、原文字数、摘要字数、压缩比；点开进入对照阅读，左边原文、右边摘要和要点 |
| RES-06 | P0 | 人工复核·修正意图：任务完成后（运行中、暂停时也可以）在结果表按 E 或在条目详情里修改处理成功的条目。只能改成该任务所用提示词里列出的类别（05 第 4.6 节）；提示词没有按格式列出类别时不能修正，并说明原因。改成模型原来的类别等于撤销修正。修正后标记“人工修正”，同时显示模型原来的类别；线网图、类别筛选、统计和导出使用修正后的值，导出另有“修正前意图”列 |
| RES-07 | P0 | 标记“已复核”：结果表按空格、条目详情和对照阅读里点“标记已复核”；修正意图或修改摘要时自动标记。可按“人工修正、已复核、未复核”筛选 |
| RES-08 | P1 | 类别合并与改名（例如把“查物流”并入“物流查询”）：只影响展示、统计和导出，不改模型原始输出 |
| RES-09 | P1 | 摘要溯源连线：鼠标移到要点上，原文中对应段落高亮并连线（内置摘要提示词已输出段落编号） |
| RES-10 | P1 | 统计面板：tokens 用量、耗时分布、失败原因分布 |
| RES-11 | P0 | 人工复核·修改摘要：在对照阅读里修改处理成功的条目的摘要主旨（要点保持模型输出），可以撤销；修改后标记“人工修正”，可以展开查看模型原来的摘要；结果表、字数、压缩比和导出使用修改后的摘要，导出另有“修正前摘要”列 |

## 5. 非功能需求

| 类别 | 要求 |
|---|---|
| 架构 | 前后端分离：`frontend/` 与 `backend/` 是两个独立工程，各自有依赖清单、启动命令、测试和 README；前端只通过 04 定义的 HTTP 接口与后端通信，不引用后端代码；前端可以单独部署，通过构建变量指向任意后端地址；后端可以脱离前端单独运行，自带接口文档 `/docs`。打包版和源码一键启动时由后端托管已构建的前端，只是部署方式，不改变分离的结构 |
| 源码 | 项目根目录就是完整、可读的源码；exe 是另外生成在 `release/` 里的打包版 |
| 性能 | 双击到界面可用 ≤ 5 秒；10 万行 xlsx 出预览 ≤ 3 秒、统计完总行数 ≤ 15 秒；结果表 10 万行滚动不掉帧（≥ 55 fps）；界面更新合并后每秒不超过 10 次；处理 10 万行的任务时后端内存 ≤ 600 MB |
| 可靠性 | 每条结果完成后 500 毫秒内落库；程序崩溃或退出最多丢失正在进行中的那几条，重新打开后可以继续 |
| 安全 | 后端只监听 `127.0.0.1`；API Key 加密存储，日志、导出文件、接口返回都不含明文密钥；上传文件只存在本机 |
| 兼容 | Windows 10 22H2 及以上、Windows 11，x64；界面运行在新版 Edge 或 Chrome 中；窗口最小 1100 × 700，针对 1440 到 2560 宽度优化 |
| 可用性 | 全部操作可以只用键盘完成；焦点始终可见；文字对比度满足 WCAG AA；尊重系统“减少动态效果”设置 |
| 离线 | 界面所需的全部资源（脚本、字体、图标）随程序分发，断网也能打开界面；只有调用模型时需要网络 |
| 可维护性 | 后端核心模块（解析、渲染、解析输出、任务引擎、导出）测试覆盖率 ≥ 80%；前端接口类型由后端 OpenAPI 自动生成 |

## 6. 不做的事

- 多用户、登录、权限；
- 扫描件 OCR、图片和音视频；
- 模型微调、本地模型的下载和管理（本机模型用 Ollama、vLLM 等自行启动，再按 OpenAI 兼容接口接入）；
- 一个任务同时做识别和摘要；
- 云同步、远程访问。

## 7. 已确认的决策

| 决策 | 结论 |
|---|---|
| 使用场景 | 单用户，本机，免登录 |
| 数据粒度 | 一行就是一条数据，先把按行处理做扎实；docx、pdf 和整篇切分放到 P1 |
| 并发 | 两种任务各自设置，默认 5，最大 20 |
| 处理条数 | 默认 100，可设为“全部” |
| 意图类别 | 写在提示词里，模型输出什么类别就汇总什么，类别数量不预设。人工修正只能改成提示词里列出的类别（按“- 类别名：说明”逐行列出，05 第 4.6 节），不支持改成提示词之外的类别 |
| 人工复核 | 修正意图、修改摘要只改人工字段，模型的原始输出保留；界面同时显示修改前后，导出用修改后的值并附修改前的值。单条重新处理只重置模型结果，人工修正和复核标记保留 |
| 工程结构 | 前后端分离，源码完整可见，根目录、`backend/`、`frontend/` 各有 README |
| 启动方式 | 两种一键启动：双击 `release\WenShu\WenShu.exe`（打包版，不需要装环境）；双击项目根目录的 `启动文枢.bat`（源码版）。两者行为一致，默认弹出 Edge 应用模式的独立窗口。开发时用 `scripts\dev.bat`，前后端分别热更新 |
| 技术栈 | 后端 Python + FastAPI + SQLite，前端 Vue 3 + Vite + TypeScript |
| 视觉方向 | “意图路由图”：地铁线路图的视觉语言，亮色为主，另有暗色主题 |
| 产品名 | 文枢（WenShu），exe 为 `WenShu.exe`；名称集中在一个常量里，可以改 |
