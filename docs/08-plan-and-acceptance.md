# 08 开发计划与验收

> 文枢开发文档 · 第 8 篇。把第一版（全部 P0）拆成 7 个阶段。每个阶段可以整体交给一个 agent，做完、验收通过再进入下一阶段。

## 1. 怎么用这份计划

```
0 ──▶ 1 ──┬──▶ 2 ──┬──▶ 4 ──▶ 5 ──▶ 6
          └──▶ 3 ──┘
```

阶段 0 脚手架、1 后端基础、2 任务引擎、3 前端基础、4 任务流程界面、5 打磨、6 一键启动与打包。

- 阶段 1 完成后，阶段 2（后端）和阶段 3（前端）可以由两个 agent 同时进行；阶段 3 用到阶段 1 的接口，不能更早开始；
- 阶段 4 要等阶段 2、3 都完成；
- 每个阶段的任务编号（如 `T2-3`）在提交说明里引用；
- 每个阶段结束时，agent 必须逐条跑完“验收”并报告结果，同时列出发现的文档问题；
- 文档有矛盾时，以 03（数据库）和 04（接口）为准，并在报告里指出。

验收（全部使用演示模型，环境变量 `WENSHU_MOCK_FAIL_RATE=0`；每一条开始前先调用 `POST /mock/v1/_reset`。需要 `X-Mock-Behavior` 的，新建一个地址指向本机 `/mock/v1`、带该请求头的模型，因为内置演示模型不允许改请求头）：

- [ ] 对 1,000 行 xlsx 做意图识别，并发 20：60 秒内完成，计数正确；`GET /mock/v1/_stats` 的 `max_inflight` 不超过 20；
- [ ] 两个任务同时使用同一个模型，模型并发上限设为 8、两个任务并发各 10：`max_inflight` 不超过 8；
- [ ] 并发 5、处理 100 条，中途暂停：`progress.running` 降到 0 后不再有新请求；继续后正确完成；
- [ ] 并发 5，暂停后立刻点继续（暂停前派发的条目还没做完）：`max_inflight` 不超过 5，没有条目被处理两次；
- [ ] 运行中对一条已成功的条目单条重新处理：它被重新请求一次，任务最终正常完成，不会一直停在运行中；
- [ ] 关闭去重、请求头 `X-Mock-Behavior: rate_limit_first`：全部成功，每条 `attempts = 2`，尝试记录里有 429。开启去重时，主条目 `attempts = 2`，跟随条目为 0；
- [ ] `X-Mock-Behavior: auth`：任务自动暂停，`status_reason_code = auth_failed`，原因为“模型密钥无效或无权限（HTTP 401）”，没有失败条目；
- [ ] 关闭去重、`X-Mock-Behavior: bad_json`：条目失败，`error_code = PARSE_ERROR`，`attempts = 2`（含一次纠正请求），原始输出已保存；
- [ ] `X-Mock-Behavior: server_error`：连续 10 条失败后任务因熔断暂停，`status_reason_code = circuit_breaker`，这 10 条为失败；
- [ ] 模型上下文长度设为 4096，对一条 2 万字文本做摘要：`chunk_count > 1`，发生了多轮合并（尝试记录里有不止一次 `merge`），结果有要点和段落编号。（上下文设为 2048 时，内置摘要模板的输入预算不到 256，条目会以 `CONTEXT_TOO_SMALL` 失败，这同样是预期行为，可以另做一条用例）；
- [ ] 去重：模板里用了 `{{row_number}}` 时，两行原文相同也不会被合并；
- [ ] 导出：原文以 `=` 开头、或含 `\x0b` 等控制字符时，xlsx 和 csv 都能导出，Excel 打开不报错、不把它当公式；
- [ ] 运行中直接结束进程再启动：任务变为已暂停且原因正确；继续后完成，已成功的条目没有被重复请求；
- [ ] 导出的 xlsx、csv 用 Excel 打开中文正常，列与 04 第 9 节一致；
- [ ] 用 `curl -N "http://127.0.0.1:18765/api/events?job_id=1"` 能看到 `job.updated`、`items.updated`、`tracks.updated`、`event: ping`（具名事件，不是注释行）；
- [ ] 有事件流连着时调用 `POST /api/system/shutdown`（用打包或源码方式启动时）：3 秒内进程退出；
- [ ] pytest 覆盖第 10.1 节“引擎”“导出”“接口”的全部用例。

| 输出解析 | 纯 JSON；代码围栏里的 JSON；JSON 前后有说明文字；可修复的残缺 JSON；只含一个对象的数组；置信度 `0.9`、`"0.9"`、`"85%"`、`85`、`"高"`；05 第 4.5 节的类别规范化；完整的 `<think>` 块；只有 `</think>`；`reasoning_content` 字段；要点为字符串数组、对象数组、来源为单个整数；超出范围的来源被过滤；纯文本模式的前缀去除 |
| 切分与截断 | 同一文本两次切分结果完全相同；超长段落按句切分；单句超长硬切；截断后长度符合预算、省略字数正确 |
| 分段合并 | 小上下文下 `chunk_count` 正确；合并内容过长时多轮合并 |
| 加密 | 加密解密往返；掩码；接口和日志里没有明文；PATCH 时 `api_key` 不传和传空字符串都不改，传 `null` 清除 |
| 模型调用 | 设置了 `HTTPS_PROXY` 环境变量时，`proxy_url` 为空的模型仍然直连；`CONTEXT_TOO_LONG` 的判定不会误伤含 `max_tokens` 的报错；`OUTPUT_TRUNCATED` 在最大输出已 ≥ 8192 时不重试 |
| 演示模型 | 分段第 1 段不会被当成合并请求；随机故障不注入试运行和测试连接；`_stats`、`_reset` |
| 引擎 | 任务级并发上限；模型级共享上限；暂停、继续、取消；暂停后在收尾时继续，不叠加并发；全部条目都在处理时暂停再继续，任务做完才转为 completed；暂停期间恰好做完时保持 paused，继续时转为 completed；运行中单条重跑；正在处理的条目单条重跑返回 409；结果落库前不会被重复派发；某一条抛出意外异常不影响其他条目；重试失败项；去重跟随条目同步结果；鉴权暂停（条目回到 pending）；熔断（条目保持 failed）；上下文超长兜底；启动恢复（原因码 `shutdown`）；计数重算 |
| 导出 | 两种任务类型的列；结果列重名加后缀；csv 带 BOM；xlsx 第二个工作表；以 `=`、`+`、`-`、`@` 开头的文本；控制字符；超过 32,767 字的单元格；人工修正后“意图”“摘要”为修改后的值、“修正前意图”“修正前摘要”为模型的值 |
| 人工复核 | 05 第 4.6 节取类别的两条规则（标题小节、`- 类别名：说明` 行）；修正成列出的类别后有效类别、类别统计、`corrected` 筛选随之变化，并自动标记已复核；先规范化再比较；不在列表里返回 `LABEL_NOT_IN_PROMPT`；提示词没有列出类别时不能修正；未成功的条目返回 409；改回模型的类别等于撤销；修改摘要后摘要预览、字数、压缩比、浓缩计按修改后的计，模型原摘要保留；单条重新处理后人工修正保留 |
| 接口 | 统一错误结构；校验错误为中文；各个 409 场景；缺少 `X-WenShu-Client` 返回 403，`OPTIONS` 不受影响；设置 `WENSHU_CORS_ORIGINS` 后跨来源预检通过；`/favicon.svg` 等 static 里存在的文件直接返回，不回退成 `index.html`；粘贴相同内容返回 `reused: true` |

### 10.4 端到端场景（Playwright，使用演示模型）

**运行环境**（`frontend/playwright.config.ts`）：端到端测试自己启动一套前后端，用独立的端口和数据目录，与开发环境互不干扰。

- `globalSetup`：删除并重建项目根目录的 `.e2edata`；`testdata/` 缺文件时用 `backend\.venv\Scripts\python.exe scripts\make_testdata.py` 生成；
- `webServer` 两项：
  - 后端：在 `backend` 目录执行 `.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 18766`，环境变量 `WENSHU_PORT=18766`、`WENSHU_DATA_DIR=<项目根>\.e2edata`、`WENSHU_DEV=1`、`WENSHU_MOCK_FAIL_RATE=0`；就绪地址 `http://127.0.0.1:18766/api/health`；
  - 前端：在 `frontend` 目录执行 `npm run dev -- --port 5174`，环境变量 `WENSHU_API_TARGET=http://127.0.0.1:18766`；就绪地址 `http://127.0.0.1:5174`；
  - 两项都 `reuseExistingServer: false`；
- `use: { baseURL: "http://127.0.0.1:5174", channel: "msedge" }`；
- 每个场景开始前（`beforeEach`）调用 `POST /api/_dev/reset` 和 `POST /mock/v1/_reset`，场景之间不共享任何数据。否则场景 D 新建的模型会因为“第一个真实模型自动设为默认”而变成后面场景的默认模型；
- 需要 `X-Mock-Behavior` 的场景，新建一个地址为 `http://127.0.0.1:18766/mock/v1`、带该请求头的模型。

端到端测试和 `testdata/` 横跨前后端，是 AGENTS.md 第 9 条（前后端互不引用）的明文例外：Playwright 可以启动后端、运行 `scripts/make_testdata.py`，但前端的应用代码仍然不能引用后端。

| 场景 | 步骤与断言 |
|---|---|
| A 意图识别主流程 | 首页拖入 `intent_200.xlsx` → 自动选中“用户问题”列 → 意图识别、并发 5、处理 100 条 → 开始；断言并行轨道最多 5 行；完成后线网图至少 3 条线路；点击一条线路，结果表只剩该意图；按 Enter 打开条目抽屉，看到发送内容；导出 xlsx，下载成功 |

| E 暂停继续 | 并发 2、处理 50 条 → 运行中按 P 暂停 → 断言状态“已暂停”，轨道上的条目处理完后为空闲 → 再按 P 继续 → 完成，成功数为 50 |

| G 人工复核 | 意图识别完成后打开第一条 → 按 E，菜单只列提示词里的类别 → 改成另一个类别 → 抽屉显示“人工修正”和“修正前”，自动标记已复核 → 结果表这一行有修正标记 → “复核”筛选选“人工修正”只剩这一条 → 撤销修正；文本摘要完成后在对照阅读里修改摘要 → 显示“人工修改”，展开“模型原摘要”看到原来的摘要 → 导出的 CSV 里“摘要”是修改后的内容、“修正前摘要”是模型的摘要 |
